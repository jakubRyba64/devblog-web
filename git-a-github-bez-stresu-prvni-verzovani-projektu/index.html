    Git a GitHub bez stresu: první verzování projektu

    Publikováno (6. května 2026)

    Přejít na část

    Proč verzovat kód První repozitář a commity Větve a bezpečné experimentování GitHub a sdílení projektu

    Ztratili jste někdy funkční verzi projektu, protože jste ji přepsali? Přesně proto existuje verzovací systém. Git ukládá historii všech změn a umožňuje se kdykoli vrátit zpět.

    GitHub ho doplňuje o online úložiště, kde může projekt sdílet, zálohovat a ukazovat v portfoliu.

    V tomto článku si projdeme první verzování projektu krok za krokem — od instalace po první nahrání na GitHub.

    1 — Proč verzovat kód

    Bez verzování vznikají soubory typu final, final2 a final-opravdu-final. Git tento chaos řeší: každá uložená změna (commit) má čas, autora a popis.

    Historii si můžete prohlédnout, porovnat verze nebo se vrátit k poslednímu funkčnímu stavu. Když něco rozbijete, nic se skutečně neztratí.

    Verzování navíc buduje dobrý pracovní návyk: malé kroky, jasné popisy a kontrola nad tím, co a kdy se změnilo.

    2 — První repozitář a commity

    Repozitář založíte příkazem git init ve složce projektu. Soubory pak přidáváte pomocí git add a ukládáte příkazem git commit s popisnou zprávou.

    Zásada zní: jeden commit = jedna logická změna. Přidání stylů a oprava chyby patří do dvou různých commitů.

    Do repozitáře nepatří vygenerované soubory ani hesla. Pro výjimky slouží soubor .gitignore, který Git při ukládání ignoruje.

    3 — Větve a bezpečné experimentování

    Větev je samostatná linka vývoje. Na hlavní větvi zůstává stabilní verze projektu a nové nápady vyvíjíte ve vlastní větvi, kterou po otestování sloučíte zpět.

    Díky tomu můžete experimentovat bez strachu — hlavní větev se nemění, dokud nová funkce není hotová a vyzkoušená.

    Na začátek stačí tři příkazy: git branch pro vytvoření, git checkout pro přepnutí a git merge pro sloučení. Zbytek přijde s praxí.

    4 — GitHub a sdílení projektu

    Repozitář na GitHubu propojíte pomocí git remote add a nahrajete příkazem git push. Od té chvíle máte kód zálohovaný online a dostupný odkazem.

    Veřejný repozitář je nejlepší vizitka vývojáře. K projektu přidejte soubor README s krátkým popisem, postupem spuštění a ukázkou výsledku.

    Nebojte se ukazovat i menší projekty — ukazují, že dokážete práci dotáhnout do konce.

    4 výhody verzovacího systému Git

    • Přehledná historie všech změn v kódu
    • Bezpečné experimentování v samostatných větvích
    • Záloha projektu online přes GitHub
    • Veřejné projekty použitelné v portfoliu
